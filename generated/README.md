# generated

生成画像の正本です。分類器用などに画像を複製せず、ここに置いたものを参照します。

```text
generated/
  99_inbox/        生成直後。まだ分類していない
  0_like/
    0_reference/   既知のパターンとして残す（似た展開が想像できる）
    1_seed/        未知の方向として残す（ここから複数の派生を見たい）
  1_dislike/       興味がなく、発展させたい方向も思いつかない
  2_maybe/         何かありそうだが、手直しの方向がまだ見えない（学習には使わない）
  999_sheet/       切り出し前の元シートと、そのメタデータ。分類・学習の対象ではない（Git 管理外）
```

## 分類の考え方

この段階（発散）の目的は、**画像を見て手直しの方向を見出せるか**と、**好みのデザインが積極的に出力されるか**を確かめることです。最終的な成形は後で行うので、ここでは「そのまま使える完成品か」を問いません。

各画像について、次の 1 問だけを判断します。

> この画像を見て、具体的な変更案を 1 つ以上思いつき、その結果を見たいか？

| 答え | ラベル |
| --- | --- |
| はい。変更案が出て、見たい | `0_like` |
| 明確に興味がなく、変更案も出ない | `1_dislike` |
| 何かありそうだが、変更案が出ない | `2_maybe` |

### `0_like` の下

`0_like` は「好き」ではなく、「手直し・派生の方向が見えて、残したい」です。その中を次の 2 つに分けます。

- `0_reference`: 水玉、ストライプ、格子、七宝のように、似た展開がすぐ想像できる。コンセプトに応じて選択肢に入れたい。
- `1_seed`: 変更後の姿が想像しきれない。この画像を起点に、発散的に複数の派生を見たい。挑戦的で良いと思ったものもここに入れる。

「未知か既知か」は世の中ではなく、**自分が似た展開をすぐ想像できるか**で決めます。

### 判断で迷うとき

- 一部だけ良い（線、色、反復量が違えば良さそう）→ 変更案が具体的なら `like`、出ないなら `maybe`。
- 配色に気持ちが引っ張られて、柄の変更案を想像できないものは `dislike` でよい（配色が、柄を想像するときのノイズになっているため）。ただし色が理由の `dislike` は、柄の好みと混ざる。色と柄を切り分けた比較シート（同じ柄 × 複数の配色）で補う。
- `dislike` を無理に増やさない。曖昧なものを `dislike` にすると、条件付きで好きな方向を負例として学習してしまう。
- 迷う画像に時間をかけない。最初は第一印象で振り分け、あとで `maybe` と境界の画像を見直す。
- 点数（100 点満点など）は使わない。主観の採点はぶれやすく、今の枚数では意味を学習できない。

### この段階で評価しないこと

次は、最終成形のフェーズで評価します。発散のラベルには含めません。

- シガーボックスが回転する道具であることによる上下・左右の方向性（例: 山、花の向き）
- 印刷や貼りやすさ

上下が明確なデザインでも、「上下のない模様に直す」といった変更案が思い浮かぶなら `like` にしてよい。ただし、画像の方向性を気にして迷うなら、画像を 180 度回転して見ると判断しやすい。

## ルール

- 画像ごとに、同名の `.json` でメタデータ（`source`: 生成元、`prompt`: プロンプト、`cell_description`: シートから切り出した場合のマスの説明）を残す。画像から分かること（サイズ）、ディレクトリで分かること（ラベル）、ファイル名に入っていること（日時）は書かない。
- 画像の比率は 3:2 に揃える（最終用途の面が 180x120mm / 165x120mm のため）。
- `2_maybe` は分類器の学習には使わない。好みの境界を把握するために残す。
- 分類を変えるときは、ファイルを別のディレクトリへ移す。過去の分類器がどのラベルを使ったかは、`scorers/vNNN/manifest.json` に固定されている。

## 分類器に使うとき

`0_like` 全体を、同じ重みの「好き」としては扱わない。`0_reference` と `1_seed` は役割が違うため、分類器を作る時点で、片方だけを使う、重みを変える、などを決めて `manifest.json` に残す。
