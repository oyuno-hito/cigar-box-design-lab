# プロンプト 10 本ノック

お題を 1 つ決め、プロンプトを 10 本作り、1 本につき 1 枚だけ生成して、結果を評価する。評価の結果で `docs/style-spec.md` を更新する。1 回約 10 分（生成は 4 分ほど、残りは評価と記録）。回数を指定されたら、お題を変えて繰り返す。

`/tune-prompts` との違い: あちらは既存の題材で 12 枚ずつ増やして打率を見る。こちらは**新しい題材で 1 枚ずつ、幅広く**試して、句が題材をまたいで効くかの証拠を積む。「確認済み」に必要な「2 つ以上の別の題材」は、主にこのスキルで貯める。

## 守ること

- **探索（発散）には使わない。** このスキルは、題材が決まったあとの生成プロンプトの調整だけをする。お題を考えるときは `docs/style-spec.md` の好みを使わない（好みに寄ったお題ばかりになるため）。プロンプトに変換する段階から読む。
- **お題（題材）は、10 本とも同じ文にする。** 変えるのは描き方（軸）だけ。
- **1 本のプロンプトで変える軸は 1 つ**（併用の 3 本と、全部入りの対照を除く）。
- **様式名は書かない。** 軸の語彙で書く（`docs/style-spec.md` の「軸の語彙」）。
- プロンプトは英語。negative は使わない（XL Turbo-Lightning ではほとんど効かない）。避けたい性質は、反対側を肯定する句にする。
- 1 本につき 1 枚。seed は、**10 本とも同じ値**にする（構図の揺れを減らすため。セッションごとに別の値を選んでよい）。
- **1 枚では偶然が大きい。** 1 回の結果で「確認済み」にしない。状態を変えるのは、`docs/style-spec.md` の昇格の条件を満たしたときだけ。
- コミットはしない。`generated/` には何も入れない。

## 前提

ComfyUI が起動している（`http://127.0.0.1:8188`）。`.venv` を有効化できる。`scorers/` に分類器がある。

## 手順

### 1. お題を決める（質問せずに決めて、伝える）

- ジャグリングの道具の面に貼る絵の題材として自然なもの（曲、モチーフ、素材、季節、場面など）から 1 つ。
- 次は避ける: **人物・手・建物・室内**が主役になるお題（写実に倒れやすいと分かっている）。過去に使ったお題（`docs/style-spec.md` の「句の戦績」「履歴」と `runs/` のディレクトリ名で確認する）。
- 過去と**違う種類**を選ぶ（例: 曲 → 自然現象 → 素材 → 季節行事 → 抽象概念）。
- 1 文の英語の題材文にする（例: `rain falling on a pond at dusk`、`a swarm of fireflies over tall grass`）。10 本すべてに、この文をそのまま入れる。

### 2. プロンプトを 10 本作る

共通の土台（`base`）は、`flat graphic decoration, full frame composition, <題材文>`。ここに句を足して作る。句は `docs/style-spec.md` の「試す句の案」（ID は `color` / `fine` / `flat` / `depth` / `abstract`）を、お題に合わせて書き直して使う（`color` は、お題の色味に合わせて主役の色を入れ替える）。

| # | label | 内容 |
| --- | --- | --- |
| 01 | `base` | 土台だけ |
| 02 | `+color` | 土台 + 色の階層の句 |
| 03 | `+fine` | 土台 + 線・点の細かさの句 |
| 04 | `+flat` | 土台 + 面の処理の句 |
| 05 | `+depth` | 土台 + 奥行きの句 |
| 06 | `+abstract` | 土台 + 具象度の句 |
| 07〜09 | `combo-…` | 併用。「句の戦績」で良かった句の組み合わせ。戦績がなければ `color+fine`、`flat+depth+abstract`、全部入りの順 |
| 10 | `control` | **対照**。避ける方向の性質を、わざと肯定形で書く（例: 複数の高彩度色が全面で発光、細い放射線を全面に、金属の反射と落ち影、奥行きのある空間）。観察した「避ける方向」が本当に嫌われるかを確かめる |

`style-spec.md` に「確認済み」の句があれば、`base` ではなく、それを土台に入れた版を `base` にし、土台だけの版は 1 本追加せずに省く（10 本に収める）。その場合は spec の note に書く。

### 3. spec を作って流す

`runs/<日時>-eval-prompts-<お題のスラッグ>/spec.json` を作る（形式は `runs/README.md`）。

- 条件は 1 つ（名前は `p`）。`prompt_prefix` と `prompt_suffix` は空、`negative_prompt` も空。
- `items` は 10 件。各 `text` は**そのプロンプトの全文**、`label` は上の表の label、`id` は `01`〜`10`、`seed` は全件同じ値。
- モデルとサンプラーは、`docs/style-spec.md` の「モデルのメモ」の XL の設定（`checkpoint`、`width` 1152、`height` 768、`sampler`）。

```bash
python3 tools/run_generate.py runs/<run-id>        # バックグラウンドで実行（約 4 分）
.venv/bin/python tools/score_run.py runs/<run-id>
python3 tools/make_report.py runs/<run-id>
.venv/bin/python tools/montage.py runs/<run-id> --sort id
```

### 4. 評価する

1. **まず自己評価を書く**（人間のレビューを見る前に）。`montage.py` のシートを見て、画像ごとに:
   - 軸の語彙で、見えたこと（色の階層、線・点の細かさ、面の処理、奥行き、具象度、文字状の模様 など）を短く書く。
   - 「明確に OK / 明確に NG / 保留」を付ける。
   - 結果を `self_review.json`（`{"ok": [...], "ng": [...], "notes": {"01": "…"}}`）に保存する。`review.json` とは混ぜない。
2. **人間のレビューを頼む。** `python3 tools/make_report.py runs/<run-id> --serve` で、その run のレポートを開いてもらう（サーバーが動いていれば、一覧 `http://127.0.0.1:8765/` から開いてもらう）。印は、機械の判定に同意しない画像だけ。「最後まで見た」にチェックし、「review.json に保存」を押してもらう（`report.html` と同じディレクトリに書かれる）。チャットで「03 と 05 が OK」のように返ってきたら、それを使う。待たずに先へ進む場合、結果は「(自)」付きで記録する。
3. **突き合わせる。** 人間の判定、機械の通過、自己評価の食い違いを、画像 id で一覧にする。食い違いは、次の自己評価の改善材料として `docs/style-spec.md` の観察に書く。

```bash
python3 tools/summarize_runs.py runs/<run-id>
```

### 5. 学んだことを判定する

10 本の結果から、句ごとに判定する。

- 単独の句（02〜06）は、`base`（01）と比べる。
  - 句あり = OK、`base` = NG → その句に有利な 1 件。
  - 句あり = NG、`base` = OK → その句に不利な 1 件。
  - 両方 OK または両方 NG → 差なし。ただし**両方 NG のときは、他の軸が足りない**可能性があるので、画像を見て理由を軸で書く。
- 対照（10）が NG なら、観察した「避ける方向」の裏付け。対照が OK なら、その軸は思い込みの可能性があるので、観察の状態を見直す。
- 併用（07〜09）は、単独の戦績には数えない。履歴に結果だけ書く。
- 予想外の発見（句と無関係に目に付いたこと）は、軸の語彙で観察に書く。収まらなければ軸を足す。

### 6. `docs/style-spec.md` を更新する

- 「句の戦績」の表に、**句ごとに 1 行**（題材・句あり・`base`・日付・run）。
- 「好みの記録」の観察の行: 根拠の追記、状態の更新。昇格の条件（「状態の意味」の「確認済み」「却下」）を、戦績の表で確かめて、満たしたものだけ変える。**人間のレビューがない（自）の結果では、「確認済み」にしない。**
- 「試す句の案」: 効かなかった句や、書き方に問題があった句は、直す（直した理由を履歴に書く）。
- 「モデルのメモ」: 新しく分かったモデルの癖。
- 「履歴」に 1 行（日付、run、お題、結果の要約）。

### 7. 報告する（日本語で）

- お題と、その理由
- 10 本のプロンプト（label と全文）と、各画像の評価（人間 / 機械 / 自己評価）の表
- 句ごとの判定（有利 / 不利 / 差なし / 他の軸が足りない）
- `style-spec.md` の変更点（状態が変わった行、新しい観察）
- 評価が暫定（自己評価のみ）の部分
- 「確認済み」まであと何題材か、次のお題の候補

### 繰り返す場合

「N 回」と言われたら、1 回ごとに手順 1〜7 を回す。お題は毎回変える。2 回目以降は、前回の戦績で「併用」の組み合わせを選び直す。人間のレビューを待たずに進める場合は、**全回が（自）になる**ので、`style-spec.md` の状態は「観察」止まりと明記する。
