# sessions

実際に使うデザインを、AI と対話しながら選んで仕上げるための出力先です。実験の記録（[runs/](../runs/README.md)）とは目的が違い、**採点・レポート・人間の評価（好み / 一致）は作りません**。

```text
sessions/<日時>-<名前>/
  spec.json        お題・コンセプト・プロンプト（項目の追加で増える。形式は runs/ の spec.json と同じ）
  state.json       いまのカード、試した案、段階（準備完了 / 生成中 / エラー）、履歴。分類器のスコアは内部値としてここにある
  images/          生成画像（PNG）と同名の .json（プロンプトと生成元）
  cards/           カードのページ用の WebP（幅 960）
  selection.json   ページで選ばれた内容（選んだカード / 個別の方向 / 全体の方針 / 押したボタン）。再生成・追加すると、履歴（state.json）へ移して消える
  job.json         実行中の処理（サーバーだけが書く。終わると消える）
  compose_result.json   AI が書いたプロンプト・方針・理由（メモがあるときだけ）
  compose_logs/    AI への依頼と返答の記録（デバッグ用。毎回残る）
```

## Git での扱い

- この README 以外は **Git 管理外**（`.gitignore`）。画像は、`tools/check_staged.py` でも止まる。
- 例示として 1 件だけコミットするときは、そのディレクトリの `spec.json` と `state.json` を `git add -f` する（画像は入れない）。

## 流れ

`.cursor/skills/design-workflow/SKILL.md` の「実使用のフロー」を正本とする。前半（候補を絞る）が実装済みで、後半（1 枚ずつの微調整）は未実装。コマンドは次のとおり。

```bash
uv run tools/session.py new brief.json            # session を作る（brief は tools/new_eval_run.py と同じ形式。既定 8 件。崩れた JSON は補正して読む）
uv run tools/session.py generate sessions/<id>    # 最初の候補を生成する（バックグラウンドで実行）
uv run tools/serve_session.py --host tailscale    # カードのページを配信する。URL が表示される
uv run tools/session.py selection sessions/<id>   # ページで選ばれた内容を読む
uv run tools/session.py plan sessions/<id>        # 選択から、作る候補の計画と、AI への依頼文を出す
uv run tools/session.py regen sessions/<id> --auto [--prompts out.json]   # 計画どおりに再生成する（バックグラウンドで実行）
uv run tools/session.py regen sessions/<id> --items new.json              # AI が書いた項目で再生成する
uv run tools/session.py add sessions/<id> --auto  # 足りない分を補う（バックグラウンドで実行）
uv run tools/session.py status sessions/<id>      # 段階と進捗、足りない件数（shortfall）
```

通常は、ページのボタンを押すと、サーバーが `regen --auto` / `add --auto` を起動する。コマンドは、チャットの AI が直接進めるとき用。

## 件数と再生成のルール

- カードは `size` 件（既定 8）。生成直後に分類器で判定し、しきい値未満の画像はカードになる前に削除する。採用済みカードを、後からスコア順に削除することはない。
- 通常の探索では、**1 プロンプトにつき 1 枚**生成する。同じ `idea_id` に複数の prompt がある場合、最初にしきい値を超えた 1 枚を採用し、そのアイデアの残りは生成しない。
- 予備のアイデアを使い切っても足りないときは、**再生成では AI を呼ばない**（足りない件数が出る）。人が「足りない分を補う」を押したときだけ、AI に新しいアイデアの prompt を依頼する。
- 残すカード = **選んだカードだけ**。選んでいないカードは、個別の方向が入っていても削除する（方向を書くとカードを自動で選ぶが、あとで選択を外せる）。
- 選んだカードに個別の方向があれば、元の画像を残して、**異なる prompt の派生を 3 件**作る（足切りなしで 3 件とも出す）。seed 違いを発散の手段にはしない。派生は、元の画像と**はっきり違う**ことを求める。ページでは、元のカードに「派生作成」、派生に「派生」のラベルが付く。
- 派生は、元のカードの中に隠れる（ページの「派生 n」ボタンで見る）。`size` の件数には数えない。選んだ派生だけ次に残る。元のカードを残さずに派生だけ選ぶと、派生が元のカードの代わりになる。
- 並び順は変えない（残したカードは前の順、新しいカードは、できた順）。分類器のスコアは、下位を捨てる判定にだけ使う。
- 空き枠は、まだ試していない予備のアイデアから埋める。空き枠の 5 割増を目安に候補を用意し、生成順を保つ。
- 足りないとき（`shortfall`）は、人が `add --auto`（ページの「足りない分を補う」）を押すと、予備を使い、尽きたら AI に新しいアイデアを依頼する。

## AI を使う場面

最初のアイデア出し、予備が尽きたときの追加、個別の派生 prompt の作成に AI を使う。メモなしの補充は、予備があれば手続きだけで進む。

- 個別の方向を書いたカードの派生には、全体の方針を反映しない（個別の方向だけ）。全体の方針は、空き枠を埋める新しい候補にだけ反映する（AI への依頼文に入っている）。
- 個別の派生は、同じ元 prompt の言い換えではなく、構成・密度・形の異なる prompt を 3 件作る。各 prompt から 1 枚だけ生成する。
- 派生の prompt は、方向の語句を前のほうに置いて `(語句:1.3)` の重みを付け、方向と矛盾する元の語句は取り除く。検査で、元の語句の残りは 3〜8 割、派生どうしの共通は 8 割以下、重み付きの語句があること、を確かめ、満たさなければ理由を添えて 1 回だけ頼み直す。補充（全体の方針の反映）は、元の語句を 3 割以上残す。
- AI は、カードの題名（元の方針と方向を合体させた短い日本語の方針）と、「説明」に出す採用理由も返す。最初の候補の理由は、brief の各項目の `reason` に書く。
- 呼び方は、環境変数 `CIGAR_COMPOSER_CMD`（依頼文を標準入力、返答を標準出力。例 `claude -p`）か、未設定ならページで依頼文をコピーして任意の AI に貼り、返答の JSON をページに貼る。特定のツールには固定しない。`CIGAR_COMPOSER_CMD` を使うときは、依頼と返答が `compose_logs/` に残る。ファイルの編集やコマンドの実行をさせない設定で呼ぶこと。

## ページを開く範囲

認証がないので、届く範囲は bind するアドレスで決める。既定は `127.0.0.1`（この PC だけ）。スマホから開くときは、`--host tailscale`（Tailnet の端末だけ）にする。`0.0.0.0` は同じネットワークの全員に届くので、`--allow-any` を付けたときだけ許す。
