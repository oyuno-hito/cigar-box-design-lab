# 見本: `20261124-234236-eval-prompts-idol-structured`

曲の核を分解し、1 プロンプト 1 枚で複数の方向を試した run の見本です。ほかの `runs/` は Git 管理外ですが、この run と [gap-09-scifi](../20261124-204000-gap-09-scifi/README.md) だけ丸ごとコミットしています（理由と運用は [../README.md](../README.md)）。`gap-09-scifi` は「LLM 側と同じ指定で作って品質ギャップを測る」run、こちらは「題材の核から方向を広げ、人間が好みと一致を採点する」run です。

## 目的

YOASOBI『アイドル』（TVアニメ『【推しの子】』オープニング）を題材に、次を見る。

- 曲の核（眩しい偶像と、その裏の鋭い秘密）を分解して書いた方向案が、どれだけ「題材に合って」「好みに合う」か。
- 好み（残す / 保留 / 外す）と、題材の核との一致（強い / 部分 / 弱い）が、どう関係するか。

## 流れ

| 段階 | 誰が | 何を | 成果物 |
| --- | --- | --- | --- |
| 1. 調べる | 私（エージェント） | 公式サイト・インタビュー・MV の記事を調べ、方向の根拠にした要素を `context_sources` に記録 | `spec.json` |
| 2. 核と方向を書く | 私 | 英語のコンセプト文 1 つと、15 の方向案（`direction`）。1 つの方向 = 1 プロンプト。発散なので `docs/style-spec.md` は渡さない。末尾は `no text, no people, no hands` | `spec.json` |

| 6. 人間のレビュー | **人間** | カードごとに `好み` と `一致` をボタンで付ける | `review.json`（`ratings`） |

## 結果

読み取れること:

- 一致が強い 3 件（星・割れたハート・星夜）は、すべて残す。偶像（星）と壊れる様子（割れたハート）が、人間にも核として読めた。
- 一致が弱い 9 件は、06 を除いてすべて保留か外す。06 は粒子の散りが好みに合った例で、題材からは外れた発見。
- 自己レビューで気持ち悪いと見た 06・12 は、人間は残すにしている。気持ち悪さは好みとは別の軸として扱う。
- 機械の p は、好みと完全には揃わない（外す 7 件のうち 5 件が通過、残す 4 件はすべて通過）。

## 読み方のメモ

- `好み` は、複数のお題に共通する傾向を `docs/style-spec.md` に反映するために使う。`一致` は、この run のコンセプト文・方向分け・プロンプトのどこを直すかを判断するために使う。発散の最中に、どちらの評価も画像を落とす足切りには使わない。
- `review.json` の `reviewed_conditions` が空なのは、「最後まで見た」のチェックを入れていないため。`ratings` は全 15 件に付いている。
- 全 14 題材の集計と、そこから読んだ傾向は `docs/style-spec.md` の「追加観察（2026-11-25、人間レビュー）」にある。
- 画像は、容量のため 768x512 に縮小している。生成時は 1152x768。`images/*.json` の `source` は生成時の設定のまま。
